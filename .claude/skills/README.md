# Project skills

Skills in this folder are loaded by Claude Code for this repo. Run every script from the
repo root. Package installs and `npx` commands are run by José, never by the agent. In this
repo the design token source of truth is `src/app/globals.css` (Tailwind v4 `@theme`), and
`docs/BRAND.md` documents it. Do not create parallel token files.

**ui-ux-pro-max.** UI/UX rules and a searchable local database (styles, palettes, font
pairings, UX guidelines, GSAP presets, stack tips). Use it before building or reviewing any
UI here. Work in priority order (accessibility → touch → performance → layout → type/color →
motion) and run the pre-delivery checks at 360/375/768/1024/1440. Entry file: `SKILL.md`. Full
rules: `references/quick-reference.md`. Main script: `scripts/search.py`. Caveat: the paths in
`SKILL.md` point to another machine and will not work. Use this repo-relative call instead:
`python .claude/skills/ui-ux-pro-max/scripts/search.py "<query>" --domain <d>` (or `--stack nextjs`;
if `python` is missing, try `python3` or `py -3`). Its default palette and font suggestions
(green accent, mono-heavy pairing) were overridden by Nocturne. Do not use `--persist`, because
it would write a competing `design-system/` folder.

**ui-styling.** Tailwind utility patterns, responsive breakpoints, `@theme` customization and
accessibility patterns. Use it for layout and styling work and for focus management (the mobile
menu, skip link and `aria-*`). Entry file: `SKILL.md`. Most useful references:
`references/tailwind-customization.md`, `tailwind-responsive.md` and `shadcn-accessibility.md`
(read that one for its focus patterns only). Script: `scripts/tailwind_config_gen.py`. Caveats:
we do not use shadcn/ui or Radix, since components are hand-built. Do not run the config
generator, because Tailwind v4 here has no `tailwind.config.*`. Ignore its `npx shadcn` commands.

**design-system.** Three-layer token architecture (primitive → semantic → component) and
component state tables. Use it when adding or changing tokens in `globals.css` or when defining
a new component's default/hover/focus-visible/active states. Entry file: `SKILL.md`. Key
references: `references/token-architecture.md`, `semantic-tokens.md`, `states-and-variants.md`
and `tailwind-integration.md` (it is v3-flavoured, so translate it to v4 `@theme`). Scripts:
`scripts/generate-tokens.cjs` and `validate-tokens.cjs`. Caveat: the generate/sync scripts expect
`assets/design-tokens.{json,css}` and are not used here, because they would duplicate
`globals.css`. `validate-tokens.cjs --dir src/` is safe to run as a read-only "no raw hex" check.
Its slide tooling is out of scope.

**brand.** Voice, messaging, typography and color documentation, plus consistency checklists.
Use it when writing or reviewing `docs/BRAND.md` and for the Phase 3 brand consistency pass
(naming such as "GenDD" and "human-in-the-loop", and copy that matches PORTFOLIO-CONTENT.md
verbatim). Entry file: `SKILL.md`. Key references: `references/voice-framework.md`,
`typography-specifications.md` and `consistency-checklist.md`. Scripts are in `scripts/`
(`sync-brand-to-tokens.cjs`, `inject-brand-context.cjs` and others). Caveat: the brand to
token sync expects `docs/brand-guidelines.md` and `assets/design-tokens.*` and is not used
here. Our guideline lives in `docs/BRAND.md` and the tokens live in `globals.css`. Never rewrite
site copy with its messaging formulas. The content file is verbatim.

**banner-design.** Banner and hero composition rules: safe zones, at most two typefaces, one
primary CTA, text contrast of at least 4.5:1, headlines of at least 32px, and platform sizes.
Use it for the home hero and for Open Graph images (1200×630, Phase 3). Entry file: `SKILL.md`.
Reference: `references/banner-sizes-and-styles.md`. It has no scripts. Caveat: its
"gather requirements" questions are already answered by the approved plan, and its
`assets/banners/` output convention does not apply. OG images are generated by Next.js routes.

**slides.** HTML presentation decks with Chart.js and copywriting formulas. This site mostly
does not need it. Only the section-rhythm ideas in `references/layout-patterns.md` and
`slide-strategies.md` (one idea per section, an arc from hero to proof to depth to CTA) inform
the home page. Entry file: `SKILL.md`. It has no scripts of its own (its search tooling lives in
`design-system/scripts/`). Caveat: do not use its copywriting formulas on site content.
